# 2. change history

## 2.1. No.1 -> No.2

### 2.1.1. 変更の契機

No.1は、都市伝説・怪談等を新規創作するための**14分類軸リファレンス**として設計されていた。軸は、来歴、物語内時間、語り形式、異常源存在論、接触様式、異常作用、帰結、被害時間曲線、回避可能性、情報分布、由来説明度、現実アンカー、物語単位、伝説生成履歴から構成されていた。

この体系をRound8の正規化分析母集団406件へ適用した結果、創作上は扱いやすいが、実在伝承を比較分析するコード体系としては、**資料不足と構造上の非該当を区別できない、非物語型Entryへ物語用軸を無理に適用してしまう、異常作用M0が過大計上される**といった問題が明確になった。

### 2.1.2. 創作用リファレンスから分析用コードブックへの拡張

No.2では、目的を「創作座標系」だけでなく、既存の都市伝説・噂・怪談・俗信・異常体験を比較する**分析用コードブック**へ拡張した。

分析対象も、従来の怪談・FOAF・ジンクス等に加えて、災害流言、技術デマ、異常体験ロアまで明示的に含めた。

### 2.1.3. 分析単位メタデータの導入

同一母集団に、完成した物語、伝説ファミリ、命題型噂、体験モチーフ等が混在していたため、14軸とは別に、コード化対象の単位を宣言するメタデータを導入した。

- 伝説ファミリ
- 特定バージョン
- 物語インスタンス
- 命題型噂
- 体験モチーフ
- 流言イベント

これにより、「物語ではないため値が存在しない」ケースを、単なる欠損と区別する方向へ進んだ。

### 2.1.4. コード状態の導入

No.1では、値が確認できない場合でも既存カテゴリへ押し込む余地があった。No.2では、値そのものとは別に以下の状態を導入した。

- 明示
- 推定
- 不明
- 非該当
- 競合

最重要の修正は、**不明をM0で代用しない**ことである。

M0は「作用について情報がない」ことを意味せず、「異常対象が現れる、または命題が存在するが、追加作用を必須としないことが資料から確認できる」場合に限るとした。

### 2.1.5. 14軸内部の主な修正

Round8適用で大量の根拠不足が生じた軸を中心に修正した。

- 物語内時間
    - 命題型噂等では `非該当` を正式に認めた。
    - 伝承の成立・流通年代を主人公の活動年代へ転記しない規則を追加した。
- 語り形式
    - 単文命題、事実主張、警告、ジンクス、デマ投稿等の**命題・噂提示系**を追加した。
    - 採録資料の形式と伝承そのものの提示形式を区別した。
- 異常源存在論
    - `N14 現象・体験` を追加し、「何か正体不明の主体がいる」場合と、「異常体験はあるが独立主体を仮定しない」場合を分離した。
- 接触様式
    - `経験する`、`発症する`、`巻き込まれる`、`受信する`等の受動経験を追加した。
    - `非該当`、`不明`を正式化した。
- 異常作用
    - `M24 環境物理作用` を追加した。
    - `M25 情報誘導・行動誘発` を追加した。
    - M0と資料不足を分離した。
- 回避可能性
    - 情報検証、訂正、不拡散等、非超自然型伝承に必要な制御方法を扱える方向へ拡張した。
- 情報分布
    - 単一概念では粗いため、**流通範囲**と**特権情報保持者**の2成分へ分ける方向を明示した。
- 来歴
    - 媒体移行、再燃・再文脈化等を追加した。
- 「被害時間曲線」
    - 正の帰結や中立作用も対象にするため、**作用時間曲線**へ改称した。

### 2.1.6. この版での位置付け

No.2は、14軸という外形は維持しつつ、**実データへ適用可能な分析体系へ移行するための最初の実証的改訂**である。

Round8の406件適用結果を受け、「分類項目を増やす」より先に、分析単位、欠損、非該当、証拠状態を明示的に扱う必要が認識された。

## 2.2. No.2 -> No.3

### 2.2.1. 変更の中心

No.2でコード状態と非物語型への対応を導入した後も、旧体系での主異常作用 `M0` は278/406件と極端に多かった。

No.3では、この値を「日本の都市伝説の大半は作用を持たない」という実態とは解釈せず、**作用の観測単位自体が不足している可能性**を検討した。

その結果、従来の「異常源 → 作用 → 帰結」だけではなく、

- 誰／何に作用したのか
- 伝承世界のどの層に作用したのか

を独立して記録する必要があると判断した。

### 2.2.2. 作用レイヤーの追加

14軸そのものは維持しながら、メタデータとして**作用レイヤー**を追加した。

- L1 物語内層
- L2 受容・伝播層
- L3 越境層

これにより、作中人物への作用と、その話を聞いた・読んだ受容者への作用を分けた。

とくにチェーンレターや「この話を聞くと呪われる」型では、物語内人物だけを見ていると主要な作用を落とすため、この区別が必要になった。

### 2.2.3. 作用対象の追加

異常作用について、**誰／何が作用を受けるのか**を別に記録するため、作用対象を導入した。

主人公、他の登場人物、特定被害者、共同体、組織、物体・設備・環境、世界、読者・聞き手、次の受信者等を区別する。

これにより、「主人公は無傷だが他の人物が死亡する」伝承をM0へ落とす問題を防ぐ設計となった。

### 2.2.4. 作用レコードの導入

作用を可能な限り、以下の組として記録する案を導入した。

```text
[作用レイヤー] | [作用対象] | [異常源] | [接触様式] | [異常作用] | [帰結] | [作用時間曲線] | [回避可能性]
```

この段階では、同一伝承内に複数作用があれば複数作用レコードを持たせる設計であった。

### 2.2.5. M0付与条件の厳格化

No.3ではM0を付与する前に、少なくとも以下を確認する考え方へ強化した。

- 対象バージョンまたは主要異伝を確認したか
- 主人公以外への作用を確認したか
- 受容者層への作用を確認したか
- 環境・物体への作用を確認したか
- それでも追加作用が必須でないか

したがって、一行要約に危害が書かれていないだけではM0としない。

### 2.2.6. この版での位置付け

No.3は、14軸を維持したまま、**作用を「何が起きるか」だけでなく「誰に・どの層で起きるか」として再構成した版**である。

No.2が欠損管理の修正であったのに対し、No.3はM0過大計上を契機に、因果構造の記録粒度そのものを見直した。

## 2.3. No.3 -> No.4

### 2.3.1. 最大の理論転換

No.3までは、基本的に「都市伝説や怪談を構成する特徴を14軸で表現する」体系であった。

No.4では、分析の出発点を**伝承エントリ**へ置き直し、研究目的そのものを次のsense-making問題へ再定義した。

> 異常・不可解・不確実・偶然・危険・不可視な制度その他の、意味形成を要求する事象に対して、人々のあいだで流通する伝承が、どのような解釈・因果・規則・予測・対処を与え、それをどのように共有可能な世界モデルへ変換しているか。

これにより、「怪異の種類を分類する体系」から、**伝承が不確実な対象をどう理解可能・予測可能・対処可能な世界モデルへ変換するかを比較する体系**へ研究の中心が移った。

### 2.3.2. 観察単位を「伝承エントリ」として固定

No.4では、

> 伝承エントリとは、人々が異常・不可解・不確実な何かを理解可能なものへ変換するために共有する、独立して伝達可能な最小の意味形成モデルである。

と定義し、**1伝承エントリ = Excelの1行**とした。

登場人物、作用対象、作用、帰結、典拠が複数あっても、それだけで行を増やさない。意味形成モデルの核、すなわち「世界のルール」が安定して変わる異伝のみ別Entryを検討する方針へ転換した。

### 2.3.3. 軸とメタデータを分離

以下を分析軸ではなく管理メタデータへ移した。

- Entry ID
- Family ID
- Entry type
- Version scope
- Source / Evidence
- Evidence rank
- Coding status
- Coding memo

とくにEntry typeは、伝承内容の特徴ではなく**観察単位の形式**であるため、分析軸から外した。

### 2.3.4. 14軸から16軸への再構成

No.4では旧14軸をそのまま増築せず、研究問いから16軸を再構成した。

### 2.3.5. 旧軸のうち独立軸から外したもの

- 物語内時間
    - Round8では根拠不足が多く、命題型噂や俗信へ適用しにくいため、16軸から外した。
    - 必要な物語Entryのみ補助メタデータとして扱う方針となった。
- 物語単位
    - 「1行 = 伝承エントリ」を確定したため、分析結果ではなくunitizingのメタデータへ移した。
- 伝説生成履歴

- 由来説明度

### 2.3.6. No.3の作用レコード設計を撤回

No.3では、作用対象ごとに作用レコードを複数持つ案を導入したが、No.4でこれを撤回した。

理由は、作用単位へ正規化すると、確定したrecording unitである**1伝承エントリ = 1行**を壊すためである。

以後は、1行の内部で作用対象・作用機構・帰結等をmulti-labelとして保持し、必要な場合のみ簡易対応記法を使用する方針となった。

### 2.3.7. この版での位置付け

No.4は、分類軸の調整ではなく、**研究目的・観察単位・変数体系をsense-makingの観点から再設計した最初の理論設計版**である。

### 2.4.3. データ型の導入

No.5では、各分析軸をExcelへ実装するため、次の5データ型を明示した。

- S: Single nominal
- O: Ordinal
- H1: Hierarchical single
- H3: Hierarchical primary-secondary
- B: Binary vector

これにより、理論上の1軸を「単一カテゴリ」「順序尺度」「階層分類」「主副を持つ階層分類」「複数bit」のどれとして保存・分析するかを分離した。

### 2.4.4. Parent / Child と Primary / Secondary の導入

階層型軸では、

- Parent / Child = 分類粒度
- Primary / Secondary = 1Entry内での構造的重要度

として、両者を直交する概念として整理した。

H3では、

- Primaryは必ず1つ
- Secondaryは0〜2個
- Secondary間に意味上の順位はない

とした。

また、ChildからParentが一意に決まるmany-to-one構造を前提とし、Parentは原則としてChildから自動導出する設計とした。

### 2.4.5. Tidy dataと情報量評価

「1伝承エントリ = 1行」「1分析変数 = 1列」を基本としつつ、階層コードは複数の物理列へ展開してよいとした。

さらに、Parentレベルを母集団比較の標準粒度とし、パイロット後に以下を評価する方針を導入した。

- Shannon entropy
- normalized entropy
- effective category count
- rare code率
- U率
- NA率
- intercoder agreement
- 次元間冗長性

重要なのは、**カテゴリ数やentropyを最大化すること自体を目的にしない**ことである。Entry_IDのように全件を識別できても、研究上の比較変数として意味がなければ分析軸として有用ではないと整理した。

### 2.4.6. この版での位置付け

No.5は、No.4で確立したsense-making理論を、**統計比較可能な21変数へ分解し、データ構造まで明示した版**である。

## 2.5. No.5 -> No.6

### 2.5.1. 21軸自体は維持

No.5からNo.6では、21という概念数を増減させることより、**21分析軸とExcel上の多数の保存列を混同しないこと**が主な課題となった。

そのためNo.6では「分析軸」という表現をさらに精密化し、**21概念次元（theoretical dimensions）**として位置付けた。

### 2.5.2. 理論・コーディング・分析の三層モデル

No.6では、体系を以下の三層へ分離した。

1. 理論層 — Conceptual Dimensions
    - 研究上、互いに区別して問う21の概念次元
2. コーディング層 — Atomic Coding Fields
    - コーダーが実際に入力するChild、Primary/Secondary、Status等
3. 分析層 — Derived Analysis Fields
    - Childから自動導出されるParent等、集計・entropy・比較に使う値

これにより、理論上の変数と、保存都合で増えるExcel列を明確に分けた。

### 2.5.3. 「21概念次元 ≠ 21列」を明文化

H1/H3ではParent/Child列、Primary/Secondary列が増え、D18のようなB型では複数bit列を持つ。

しかし、列数が増えても研究質問が同じであれば同一概念次元である。

例えば作用機構で、Primary 1件とSecondary 2件を保存しても、3次元ではなく、すべて「因果源が対象へ何をするか」という1概念次元の複合値であると整理した。

### 2.5.4. Parentを独立変数とみなさない

ChildからParentが一意に導出される場合、

```text
Parent = f(Child)
H(Parent | Child) = 0
```

であることを明示した。

したがって、ParentとChildは別々の情報源ではなく、**同じ概念次元を異なる解像度で見たもの**である。

Parent entropyとChild entropyを足して「この次元は情報量が多い」と評価してはならないとした。

### 2.5.5. Primary / Secondaryも別次元ではない

Primaryはその次元についてEntryを最も強く規定する値、SecondaryはPrimaryだけでは失われる独立した追加構造である。

`secondary1` / `secondary2` は保存スロットにすぎず、意味上は順不同集合として扱うことを明確化した。

### 2.5.6. Statusとworkflow statusの分離

Entry全体の作業状態と、各概念次元の証拠状態を区別した。

次元ごとのStatusは、

- D = Direct
- I = Inferred
- U = Unknown
- NA = Not applicable
- C = Conflict

とし、Entry全体の「未着手／コーディング中／レビュー待ち／確定」等のworkflow statusとは別物とした。

### 2.5.7. H3の数学的表現を明確化

H3次元を、

```text
X_d = (p, S)
p = primary child, exactly 1
S = unordered set of secondary children, 0 <= |S| <= 2
```

として扱い、Secondaryの保存位置と意味上の順位を切り離した。

また、H3の全組合せを1つの名義カテゴリとしてentropy計算すると組合せ爆発を起こすため、標準分析ではprimary_parentを中心に、secondary prevalenceや共起を別途見る方針とした。

### 2.5.8. この版での位置付け

No.6は、21次元モデルの内容を大きく変える版ではなく、**理論変数・入力値・派生値・物理列を分離し、再現可能なコーディングと統計分析へ接続するための概念整理版**である。

## 2.6. No.6 -> 現行正本（理論設計 v4）

No.6以降、このスレッドでは21概念次元の骨格を維持したまま、第1・第2パイロットおよび406件本適用の結果を踏まえて、現行正本 `docs/00_research_overview/10_urban_legend_analysis_axes_theoretical_design.md` へ更新した。

### 2.6.1. D02の再定義

旧 `初期媒体` は、伝承の「起源媒体」を推定してしまう危険があるため、**最古確認流通媒体**へ変更した。

問いは、

> 現在の証拠で、伝承が実際に人から人へ流通したことを最も古く確認できる媒体は何か

である。

したがって、推定起源ではなく、現存する証拠で確認できる最古の流通媒体をコードする。

### 2.6.2. D03の再定義

旧 `現行・主要流通媒体` は、「何をもって現在・主要とするか」を再現可能に決めにくかった。

そのため、**確認流通媒体ポートフォリオ（Version Scope）**へ変更し、「現在」「主要」という理論概念を廃止した。

D03は、今回コードするVersion Scopeの中で、実際に受容者へ流通したことを確認できる媒体を記録する。D02とD03が同じ媒体になることも許容する。

### 2.6.3. D16の再定義

旧 `作用時間構造` は、単なる時間曲線ではなく、**発動条件・原因成立から主作用／主帰結までが時間上どのように編成されるか**を測る次元として再整理し、名称を**因果時間構造**へ変更した。

現行では7 Parentの設計を採用し、単一事象内の段階進行を扱う `SEQUENTIAL_EPISODE` 等も区別する。

### 2.6.4. その他の同期

- D01の年代区分を現行9値へ同期した。
- D06を現行7値へ同期した。
- 21概念次元は維持した。
- Parent / Childは理論文書内の「候補」ではなく、`20_urban_legend_parent_child_code_system.md` で定義される現行測定体系として位置付けた。
- Child一覧、Primary選択、include / exclude条件等の詳細は理論設計から分離し、`20`と`30`へ委譲した。

### 2.6.5. 文書責務の分離

現行では、

- `10` = なぜ・何を測るか
- `20` = それをどの値で測るか
- `30` = 証拠からその値をどう判定するか

という責務分離を明文化した。

これにより、理論次元の定義とコード一覧・判定ルールの混在を解消した。

### 2.6.6. 現在の到達点

現行モデルは、

> **1伝承エントリ = 1意味形成モデル**

を21概念次元へ分解し、Parentを母集団比較の標準粒度、Childを精密記述、Primaryを次元内の中心構造、Secondaryを独立した追加構造として扱う。

```text
→ sense-makingを中心とした16軸への理論再設計
→ 複合軸を分解した21分析軸

→ パイロット結果を反映した現行21概念次元 v4
```
