## 1. 結論

Version Scopeは、1998–1999年採録で安定する「危険語の記憶期限→死亡」型へ限定されており妥当である。D07〜D16も、未来の死を条件付きで予測する規則、危険語の保持、期限、認知状態を介した危害、死亡という一貫したモデルになっている。

主要な問題はD17である。文書自身が「忘れる／記憶を失う」を直接表すChildが存在しないtaxonomy gapだと認識しているにもかかわらず、`D17.RUL.OBEY_TABOO` へ暫定写像して確定値として保持している。これはworkflowの「taxonomy不足を近似Childへ無理に押し込まない」という原則と整合しない。

D20 `DANGEROUS_TO_KNOW` も、単に知っただけでは危害が成立せず「期限まで記憶保持」が必要であるため、定義適合を再確認すべきである。

## 2. Findings

### F10-001 — D17でtaxonomy gapを認識しながら近似Childへ押し込んでいる

- 重大度: **Major**
- 現在値: `D17.RUL.OBEY_TABOO`, Status `I`

現分析は、回避方式が「期限前に『紫の鏡』を忘れること」であり、現行taxonomyに「忘れる／記憶を消す」Childがないと明示している。

これはEvidence不足ではなく、構造は明確だがコード体系が表現できない**taxonomy gap**である。

したがって、`OBEY_TABOO` を「最も近いから」という理由で確定値として保存するのは、現行workflowのTaxonomy gap QAと衝突する。

修正方針:

- `OBEY_TABOO` を通常の確定コードとして扱わない。
- 「忘却／記憶消去による制御」をtaxonomy gapとして明示管理する。
- 単一Entryだけで新Childは追加せず、横断パイロットで同構造が再現するか確認する。

### F10-002 — D20 `DANGEROUS_TO_KNOW` は定義より広く使っている可能性がある

- 重大度: **Moderate**

`D20.HAZ.DANGEROUS_TO_KNOW` の定義は「知ること自体が危険」である。

本Scopeでは、

```text
知る
＋
期限まで記憶し続ける
→ 死亡
```

であり、知識取得のみでは危害条件が完成しない。

一方で、知ることによって初めて将来の危険条件へ入り得るため、近接性はある。したがって誤りと断定はしないが、コード定義を拡張して使っていることは明示すべきである。

D20の中心質問が「誰が特権情報を持つか」であることも踏まえ、`DANGEROUS_TO_KNOW` が本Entryの情報非対称性を本当に最もよく表すかを再検討する。

### F10-003 — D07〜D16のsense-making / 因果モデルは概ね整合

- 重大度: **問題なし**

現在の構造は、

```text
D07 将来の死・運命の不確実性
→ D08 根拠未提示の危険命題
→ D09 記憶保持と死亡を相関規則化・禁忌化
→ D10 情報内容
→ D11 危険語の記憶保持＋期限年齢
→ D12 その情報を受容した聞き手
→ D13 認知状態を危害条件とする
→ D15 死亡
→ D16 期限付き
```

と読め、D07の対象、D08の契機、D09の操作、D10以降の世界モデルが分離されている。

### F10-004 — D18 L2=1は本Entryの重要な特徴として妥当

- 重大度: **問題なし／Status記述は要注意**

伝承を聞いた現実側受容者が、危険語を知ることでそのまま伝承内容上の将来の作用対象になるため、L2=1は妥当である。

ただし `L3=0` はX Evidence不在に基づく不在判定であり、L1/L2の正の直接Evidenceとは性質が異なる。D18全体をStatus `D` とするなら、bit別の根拠差を明記しておくとよい。

### F10-005 — Version Scopeの限定は妥当

- 重大度: **問題なし**

死亡型へScopeを限定し、不幸型、複合語、対抗語、人格怪異化をVariationへ分離したことで、D15等のConflictを不要に抱えない構成になっている。
