# 1. 伝承エントリ基本情報

- `Entry_ID`: `24`
- `伝承エントリ名称`: 幸福の手紙
- `Macro_Category`: 情報・メタ伝説
- `Entry_Type`: 物語・伝説

# 2. 分析概念次元

各次元は、単にコード値を記録するだけでなく、**当該伝承においてその次元が具体的にどのように現れているか**まで自然言語で記述する。

## 2.1. 来歴・流通・提示の次元

### 2.1.1. D01: 生成年代

**いつ成立したか**

- Primary Child / Value: `D01.G2` — 1945–1969
- Primary Parent: なし
- Secondary: なし
- Status: `I`

**判定根拠**

既存Pilot Codingでは戦後の郵便チェーンレターとしての流通理解に基づき `D01.G2` とされている。`0024_00_contents.md` の増補では1922年頃の日本流通を扱う研究が確認されており、現Evidenceとの不整合が生じているが、本taskではコード値自体を変更しない。

**この伝承における現れ方**

増補調査で確認した1922年頃の流通研究は、task 3で生成年代と最古確認流通年を区別して再判定する必要がある。

### 2.1.2. D02: 最古確認流通媒体

**現在の証拠で、伝承が実際に人から人へ流通したことを最も古く確認できる媒体は何か**

- Primary Child / Value: `D02.PRT.CHAIN_LETTER` — チェーンレター
- Primary Parent: `D02.PRT`
- Secondary: なし
- Status: `D`

**判定根拠**

`0024_00_contents.md` では、1920年代の日本流行が「幸運の手紙／幸運の葉書」として研究され、1951年の国会会議録でも郵便上の「幸運の手紙等」が言及されている。既存Pilot Codingは、確認可能な流通媒体をチェーンレターとする。

**この伝承における現れ方**

文面そのものが郵送され、受信者が同じ内容を複製して別の相手へ送る物理的書簡ネットワークが伝承の流通回路になる。内容の伝播と媒体上の転送が分離せず、チェーンレターという形式自体が伝承機構を担う。

### 2.1.3. D03: 確認流通媒体ポートフォリオ（Version Scope）

**今回コードするVersion Scopeで、伝承が受容者へ流通したことを確認できる媒体は何か**

- Primary Child / Value: `D03.PRT.CHAIN_LETTER`
- Primary Parent: `D03.PRT`
- Secondary: なし
- Status: `D`

**判定根拠**

既存Pilot Codingでは、Version Scopeの中心を古典的な郵便チェーンとし、チェーンレターをPrimaryに置いている。`0024_00_contents.md` でも、葉書・手紙による自己複製型の流通が歴史的な中心形として確認される。

**この伝承における現れ方**

受信者が手紙・葉書を複製して次の人へ送るため、伝承内容と流通媒体が一致する。後代には電子メールやSNS等へ移行し得るが、本Version Scopeの中心は物理的チェーンレターである。

既存末尾メモには `D03:U` と記録されていた一方、本文コードは `D03.PRT.CHAIN_LETTER / D` であり内部不整合があった。task 2では独立メモ章を廃止し、この留保を当該次元内へ移した。task 3で正本Excelと再照合する。

### 2.1.5. D05: 提示形式

**この伝承における現れ方**

幸福の手紙は、出来事を語るだけで終わらず、「あなたも同じ文面を次の人へ送れ」という行動命令を内部に持つ。受信者は読者であると同時に、次の送信者として位置付けられる。

### 2.1.6. D06: 真実性提示

**どんな「本当らしさ」を要求するか**

- Primary Child / Value: `D06.T6` — 真偽未確定
- Primary Parent: なし
- Secondary: なし
- Status: `I`

**判定根拠**

幸運発生の因果自体は検証されない一方、過去の成功例、由緒、巡回履歴等を添えることで「本当に効くかもしれない」と思わせる型がある。

**この伝承における現れ方**

受信者は、送れば必ず幸運になるという確定事実を示されるのではなく、「本当か分からないが、送れば得をするかもしれない」という不確実な信念のもとで転送を迫られる。

## 2.2. 意味形成の次元

### 2.2.1. D07: 意味形成対象

**何が不可解・不確実なのか**

- Primary Child / Value: なし
- Primary Parent: なし
- Secondary: なし
- Status: `U`

**判定根拠**

既存Pilot Codingでは、何を一義的な「不可解な対象」とするかを確定していない。候補には将来の吉凶、偶然の幸運、情報伝播と運命の接続等があるが、現行値では一つに固定しない。

**この伝承における現れ方**

幸福の手紙は、将来の幸運という制御しにくい領域を、転送行動と結び付けて理解可能にする。しかし、その中心問題を「運命・予兆」とみるか、「偶然・確率」とみるか、別の意味形成対象とみるかは既存Pilot値では確定されていない。

高密度化したEvidenceにより再判定可能性が高まっているため、task 3で改めて測定する。

### 2.2.2. D08: 意味形成契機

### 2.2.3. D09: 意味付与操作

**この伝承における現れ方**

異なる人数・期限・由緒を持つ文面であっても、「幸福の手紙」という名称により、転送すれば幸運が得られるチェーンメッセージとしてまとめて理解される。

一方、Evidenceを厚くすると「転送行動と幸運を因果規則として結び付けること」をPrimaryとみる余地がある。コード値はtask 2では変更せず、task 3の再測定対象とする。

## 2.4. 社会的埋め込みの次元

### 2.4.1. D19: 流通範囲

**誰の間に伝承が流通するか**

- Primary Child / Value: `D19.MAS.NATIONAL_PUBLIC`
- Primary Parent: `D19.MAS`
- Secondary: なし

**判定根拠**
