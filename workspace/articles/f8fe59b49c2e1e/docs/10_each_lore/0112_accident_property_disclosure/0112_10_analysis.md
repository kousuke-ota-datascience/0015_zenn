# 1. 伝承エントリ基本情報

- `Entry_ID`: `112`
- `伝承エントリ名称`: 事故物件は一度別人を住ませれば告知義務が消える
- `Macro_Category`: 制度・陰謀
- `Entry_Type`: 命題型噂
- `Version_Scope`: 「事故物件では、事故後に一人の入居者を挟めば、その次の入居者への告知義務が消える」という代表命題。2008年公開Q&Aで確認できる同型命題と、2010年代以降の反証・再流通を含む。外国人・短期アルバイト等の人物設定は派生として扱う。

一般人には見えにくい宅建実務の裏知識らしさが真実性を支え、「業者は知っている制度上の常識」として受容される。

## 2.2. 意味形成の次元

### 2.2.1. D07: 意味形成対象

**何が不可解・不確実なのか**

- Primary Child / Value: `D07.INO.HIDDEN_RULE_PROCEDURE` — 隠れた制度・手続
- Primary Parent: `D07.INO` — 制度・組織
- Secondary: なし
- Status: `D` — Direct（告知実務の境界が中心問題）

**判定根拠**

一般消費者から見えにくい「いつまで・誰まで死亡事実を告げる必要があるのか」という制度・実務の境界が、流通資料の中心問題である。

**この伝承における現れ方**

複雑な個別判断を、「一人挟む」という隠れた手続一つで説明できる裏ルールへ圧縮する。

### 2.2.2. D08: 意味形成契機

**何を手掛かりに問題化されるか**

- Primary Child / Value: `D08.OPA.OPAQUE_RULE` — 不透明な規則・判断
- Primary Parent: `D08.OPA` — 技術・制度の不透明性
- Secondary: なし
- Status: `D` — Direct（Q&A自体が制度判断の不透明さから生じる）

**判定根拠**

同じ死亡事案でも告知要否が一見して分からず、一般契約者が法律・業界実務を直接観察できないため、公開Q&Aで「何人先まで伝えるのか」という問いが立つ。

**この伝承における現れ方**

「告知されなかった＝事故がなかった」とは限らないのではないかという情報非対称が、簡単な裏ルールを求める契機になる。

### 2.2.3. D09: 意味付与操作

**不可解なものをどう理解可能にするか**

- Primary Child / Value: `D09.SSI.SYSTEM_LOGIC` — 制度論理化
- Primary Parent: `D09.SSI` — 社会構造化
- Secondary: なし
- Status: `D` — Direct（複雑な実務を単一規則へ変換）

**判定根拠**

俗説は、事故発生→一人目へ告知→一人居住→二人目から不要、という明快な制度ロジックを与え、個別判断の複雑さを入居者数という一変数へ還元する。

**この伝承における現れ方**

一般人には不透明な告知実務が、人数を数えれば結果を予測できる制度モデルへ置き換えられる。

### 2.2.4. D10: 因果源存在論

**原因を何として世界に置くか**

- Primary Child / Value: `D10.HUM.ORGANIZATION` — 組織・制度主体
- Primary Parent: `D10.HUM` — 人間・社会主体
- Secondary: なし
- Status: `I` — Inferred（制度運用・業者主体を因果源として判定）

**判定根拠**

超自然因果ではなく、貸主・管理会社・仲介業者と不動産取引制度の運用が告知状態を決めるとされる。中心命題では特定業者の悪意までは必須でないため、組織・制度主体としてコードする。

**この伝承における現れ方**

「一人挟む」手順を制度上有効なものとして理解・利用できる業界側主体が、結果を動かす原因として想定される。

## 2.3. 因果・行動モデルの次元

### 2.3.1. D11: 発動・接触条件

**何を契機に因果系へ入るか**

- Primary Child / Value: `D11.CON.LOCATION_STATE` — 位置・状態条件
- Primary Parent: `D11.CON` — 時刻・属性・状態条件
- Secondary: なし
- Status: `D` — Direct（「一人入居済み」という物件状態が条件）

**判定根拠**

俗説上、告知状態を変える条件は受容者が噂を読むことではなく、事故後に別の入居者が一度居住したという物件の履歴状態である。

**この伝承における現れ方**

同じ部屋でも「事故直後」から「一人が通常居住した後」へ状態が変わると、その次の契約で告知義務も切り替わるとされる。

### 2.3.2. D12: 作用対象

**誰／何に作用するか**

- Primary Child / Value: `D12.ORG.INSTITUTION_SYSTEM` — 制度・社会システム
- Primary Parent: `D12.ORG` — 組織・制度
- Secondary: `D12.OTH.SPECIFIC_OTHER` — 特定他者
- Status: `I` — Inferred（制度状態と後続入居者を分離）

**判定根拠**

中心命題は、入居履歴が告知義務という制度上の状態を変えるというものなので制度システムをPrimaryとする。その結果、次の入居希望者が「告知されない側」として具体的影響を受けるためSecondaryに置く。

**この伝承における現れ方**

一人分の居住履歴が入ると、業者の告知行動と後続契約者が得る情報の双方が切り替わると説明される。

### 2.3.3. D13: 作用機構

**因果源が対象へ何をするか**

- Primary Child / Value: `D13.SOC.INSTITUTIONAL_MANIPULATION` — 制度操作
- Primary Parent: `D13.SOC` — 社会・制度作用
- Secondary: `D13.SOC.CONCEAL_SUPPRESS` — 隠蔽・抑圧
- Status: `D` — Direct（制度手続利用と告知抑制が中心命題）

**判定根拠**

俗説では、一時入居者を挟むという手順により告知義務を制度的に解除し、その後の契約者へ事故歴を告げずに済むとされる。情報を信じて行動が変わることより、伝承内部の因果として制度手続そのものが操作される点をPrimaryとする。

**この伝承における現れ方**

入居履歴を意図的に一段挟むことで、物件の告知状態を変え、事故歴を次の契約者から見えなくできるというモデルになる。

### 2.3.4. D14: 帰結極性

**結果は正・負・中立・混合か**

- Primary Child / Value: `D14.MIX` — 混合
- Primary Parent: なし
- Secondary: なし
- Status: `I` — Inferred（主体ごとに正負が反転）

**判定根拠**

貸主・業者側には成約困難・価値低下を避けられる利得がある一方、後続入居者側には重要情報を知らされない不利益がある。重要な正負帰結が併存する。

**この伝承における現れ方**

同じ「一人挟む」という操作が、物件提供側には抜け道、契約者側には情報不利益として働く。

### 2.3.5. D15: 帰結領域

**何の領域が最終的に変わるか**

- Primary Child / Value: `D15.BEH.COMPLIANCE_DECISION` — 遵守・意思決定変化
- Primary Parent: `D15.BEH` — 行動・選択
- Secondary: なし
- Status: `I` — Inferred（告知する／しないという実務判断を主帰結とする）

**判定根拠**

伝承内で直接切り替わるのは、業者が死亡事実を告知するかしないかという遵守・実務判断である。金銭上の効果はその下流にあり、共有核では必須ではない。

**この伝承における現れ方**

一人の入居を挟んだ後は「もう告知しなくてよい」という意思決定へ制度状態が変わる、と理解される。

### 2.3.6. D16: 因果時間構造

**発動条件・原因成立から主作用／主帰結までの関係は、時間上どのように編成されているか**

- Primary Child / Value: `D16.STA.STATIC_RULE` — 静的規則
- Primary Parent: `D16.STA` — 無時間的・静的関係
- Secondary: なし
- Status: `D` — Direct（一般化された条件規則として提示）

**判定根拠**

具体例では事故→一人目→二人目という順序があるが、伝承として重要なのは「一人目までは告知、二人目から不要」という一般条件表であり、待ち時間や進行過程自体ではない。

**この伝承における現れ方**

何日・何年待つかではなく、入居履歴が何人分あるかという静的な条件対応として規則が記憶される。旧レビュー用メモの `D16:U` は現在のEvidenceと矛盾するため解消する。

### 2.3.7. D17: 回避・制御方式

**結果をどう回避・制御・利用できるか**

- Primary Child / Value: `D17.INF.VERIFY_DEBUNK` — 検証・反証
- Primary Parent: `D17.INF` — 情報・技術的制御
- Secondary: `D17.USE.STRATEGIC_RULE_USE` — 規則の戦略利用
- Status: `I` — Inferred（受容者側の対抗と業者側の利用を分離）

**この伝承における現れ方**

一方には制度資料で裏ルールを反証する制御があり、他方には裏ルールを利用して告知を避けるという利用法がある。

### 2.3.8. D18: 作用レイヤー

**因果効力は伝承内／受容者／社会現実のどこに及ぶか**

- Primary Child / Value: `D18.L1=1; D18.L2=0; D18.L3=1`
- Primary Parent: なし
- Secondary: なし
- Status: `I` — Inferred（伝承内規則と現実実務への波及を区別）

**判定根拠**

L1では「一人挟む→告知義務が消える」という伝承内因果が成立する。L2の「読む・聞くこと自体が受容者を因果対象にする」構造はない。L3については、2021年の業界回顧で「間に一人住まわせれば告知義務がなくなる」と業界側が有利に解釈し運用してきたとの言及があり、少なくとも噂／俗説と現実の不動産実務が接続した可能性を示す証拠があるため1とする。

**この伝承における現れ方**

単なる架空制度説明に留まらず、実務者の判断・運用として現実社会に接続したと報告される。ただし、どの程度広範だったかは現資料だけでは定量化できない。

全国から閲覧可能な不動産Q&A、匿名掲示板、一般掲示板、Webメディアで同型命題が繰り返し確認でき、特定地域・組織内部に限定されない。

**この伝承における現れ方**

### 2.4.2. D20: 特権情報保持者

**誰が真相・追加情報を持つか**

- Primary Child / Value: `D20.ORG.INSTITUTION_AUTHORITY` — 組織・権限主体
- Primary Parent: `D20.ORG` — 組織・加害主体
- Secondary: `D20.EXP.TECHNICAL_OCCUPATIONAL` — 技術・職業専門家
- Status: `I` — Inferred（物件固有情報と制度実務知識の非対称性から判定）

**この伝承における現れ方**

「業者は事故歴や抜け道を知っているが、入居希望者には見えないかもしれない」という情報非対称が俗説の説得力を作る。

### 2.4.3. D21: 現実アンカー

**実在世界へどの程度固定されるか**

- Primary Child / Value: `D21.A3` — 実在制度・社会史が成立条件
- Primary Parent: なし
- Secondary: なし
- Status: `D` — Direct（実在の不動産取引制度が成立条件）

**判定根拠**

本伝承は、賃貸・売買契約、宅地建物取引業者、人の死の告知実務という実在制度がなければ成立しない。2021年国土交通省ガイドラインが現実制度の直接アンカーになる。

**この伝承における現れ方**

説得力は「実在制度の一般人には見えない抜け道」という現実接続に依存する。架空制度へ置き換えると俗説の意味形成力が大きく失われる。
