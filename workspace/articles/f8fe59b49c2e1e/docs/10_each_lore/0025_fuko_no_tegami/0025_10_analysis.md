# 1. 伝承エントリ基本情報

- `Entry_ID`: `25`
- `伝承エントリ名称`: 不幸の手紙
- `Macro_Category`: 情報・メタ伝説
- `Entry_Type`: 物語・伝説
- `Version_Scope`: 一定人数への複製・転送を命じ、従わなければ不幸・死・災難が起こるとするチェーンレター。幸福報酬を併記する混合型は周辺異伝として扱う。

# 2. 分析概念次元

各次元は、単にコード値を記録するだけでなく、**当該伝承においてその次元が具体的にどのように現れているか**まで自然言語で記述する。

## 2.1. 来歴・流通・提示の次元

### 2.1.1. D01: 生成年代

**いつ成立したか**

- Primary Child / Value: `D01.G2` — 1945–1969
- Primary Parent: なし
- Secondary: なし
- Status: `I`

**判定根拠**

既存Pilot Codingは、戦後のチェーンレター流行、とくに1960年代末から1970年前後に不幸型が独立的に顕在化したという整理に基づき `D01.G2` としている。

**この伝承における現れ方**

1920年代から存在した幸運型チェーンの負の警告要素を背景に、不転送時の不幸を前面化した「不幸の手紙」が戦後後半に独立カテゴリとして流通する。

研究整理では顕著な流行開始が1969〜1970年頃にまたがるため、G2末端と1970年代の境界にある。task 2では値を変更せず、task 3で最初期資料と生成年代の定義を再照合する。

### 2.1.2. D02: 最古確認流通媒体

**現在の証拠で、伝承が実際に人から人へ流通したことを最も古く確認できる媒体は何か**

- Primary Child / Value: `D02.PRT.CHAIN_LETTER`
- Primary Parent: `D02.PRT`
- Secondary: なし
- Status: `D`

**判定根拠**

既存Pilot Codingは、紙の手紙を複製・郵送するチェーンとして同時代資料・研究資料で確認できることからチェーンレターを採用している。

**この伝承における現れ方**

郵便物自体が脅威の運搬体となり、受信者が同じ文面を写して別の宛先へ送ることが伝播と回避の両方を担う。

### 2.1.3. D03: 確認流通媒体ポートフォリオ（Version Scope）

**今回コードするVersion Scopeで、伝承が受容者へ流通したことを確認できる媒体は何か**

- Primary Child / Value: `D03.PRT.CHAIN_LETTER`
- Primary Parent: `D03.PRT`
- Secondary: なし
- Status: `D`

**判定根拠**

Version Scopeは古典的な郵便型を中心とし、受信・複製・郵送が同一媒体上で再帰することを重視している。

**この伝承における現れ方**

伝承内容そのものが「この手紙を次へ送れ」という命令なので、流通媒体と伝播規則が不可分である。後代には電子メール・SNSへ移行し得るが、中心Scopeは紙のチェーンレターである。

既存末尾メモには `D03:U` と記録されていた一方、本文コードは `D03.PRT.CHAIN_LETTER / D` であり内部不整合があった。task 2では独自メモ章を廃止し、留保を当該次元内へ移した。task 3で正本Excelと再照合する。

### 2.1.4. D04: 生成・変容パターン

**時間とともにどう変形したか**

- Primary Child / Value: `D04.STB.STABILIZED_CANON`
- Primary Parent: `D04.STB`
- Secondary: なし
- Status: `I`

**判定根拠**

既存Pilot Codingは、人数・期限・災厄内容・媒体が変化しても、「転送しなければ不幸になる」という脅威と転送命令が長期に保持される点を重視している。

**この伝承における現れ方**

郵便から電子メール・SNSへ媒体が変わっても、受信者を恐怖によって次の送信者へ変える自己複製規則が維持される。

### 2.1.5. D05: 提示形式

**どんなコミュニケーション形式で提示されるか**

- Primary Child / Value: `D05.RUL.CHAIN_INSTRUCTION`
- Primary Parent: `D05.RUL`
- Secondary: なし
- Status: `D`

**判定根拠**

文面が期限・人数・転送を直接命令し、受信者へ再送行動を要求する。

**この伝承における現れ方**

受容者は怪談を聞くだけでなく、「この文面を○人へ送れ」と具体的な行動手順を提示される。提示形式そのものが伝播機構として働く。

### 2.1.6. D06: 真実性提示

**どんな「本当らしさ」を要求するか**

- Primary Child / Value: `D06.T6`
- Primary Parent: なし
- Secondary: なし
- Status: `I`

**判定根拠**

文面内の災厄因果は検証されない一方、過去の犠牲者例や「無視した者に不幸が起きた」という逸話を付加して真実らしさを補強する。

**この伝承における現れ方**

受信者は「嘘かもしれないが、無視して本当に不幸になったら困る」という真偽未確定の状態に置かれ、その不確実性自体が転送圧力になる。

## 2.2. 意味形成の次元

### 2.2.1. D07: 意味形成対象

**何が不可解・不確実なのか**

- Primary Child / Value: なし
- Primary Parent: なし
- Secondary: なし
- Status: `U`

**判定根拠**

既存Pilot Codingでは、不可解対象を一つに確定していない。候補には将来の災厄、偶然の不運、情報行為と運命の接続等がある。

**この伝承における現れ方**

受信者が知りたい／制御したいのは、将来起こるかもしれない不幸である。ただし、それを「運命・予兆」とみるか「偶然・確率」とみるか、現行値では未確定である。

高密度化したEvidenceにより再測定余地があるため、task 3で再判定する。

### 2.2.2. D08: 意味形成契機

**何を手掛かりに問題化されるか**

- Primary Child / Value: `D08.CLM.UNSUPPORTED_ASSERTION`
- Primary Parent: `D08.CLM`
- Secondary: なし
- Status: `I`

**判定根拠**

「送らなければ不幸になる」という主張が、検証済み事実ではなく文面上の命題として先に提示される。

**この伝承における現れ方**

受信者はすでに起きた災厄を説明するのではなく、将来起こるかもしれない災厄を告げられ、その予告を信じるか否かという問題へ入る。

### 2.2.3. D09: 意味付与操作

**不可解なものをどう理解可能にするか**

- Primary Child / Value: `D09.CAT.NAMING`
- Primary Parent: `D09.CAT`
- Secondary: なし
- Status: `I`

**判定根拠**

既存Pilot Codingでは「不幸の手紙」という名称によって、転送を拒否すると災厄が起こるメッセージ群を一つのカテゴリとして認識可能にする点を採用している。

**この伝承における現れ方**

人数・期限・災厄内容が異なる文面でも、「不幸の手紙」という名称により同じ種類の脅迫的チェーンメッセージとして理解される。

一方、高密度化した内容からは「不転送と災厄を因果規則で結ぶ」操作をPrimaryとみる余地がある。task 2では既存値を維持し、task 3で再測定する。

### 2.2.4. D10: 因果源存在論

**原因を何として世界に置くか**

- Primary Child / Value: `D10.OBJ.INFORMATION_CONTENT`
- Primary Parent: `D10.OBJ`
- Secondary: なし
- Status: `I`

**判定根拠**

明確な人格怪異ではなく、手紙に記された情報・規則そのものが災厄効力を持つとする既存Pilot Codingを維持する。

**この伝承における現れ方**

「この情報を受け取り、連鎖を止める」という情報行為が未来の不幸へ接続される。因果源は特定の霊や人物ではなく、文面の規則として提示される。

## 2.3. 因果・行動モデルの次元

### 2.3.1. D11: 発動・接触条件

**何を契機に因果系へ入るか**

- Primary Child / Value: `D11.INF.READ_VIEW_MEDIA`
- Primary Parent: `D11.INF`
- Secondary: なし
- Status: `D`

**判定根拠**

文面を受信・読むことで規則と脅威を知り、転送するか否かの選択へ組み込まれる。

**この伝承における現れ方**

怪異地点へ行くのではなく、情報への曝露が因果系への入口となる。受信者は文面を知った時点で、自分の将来と転送行動を結び付ける規則に接触する。

### 2.3.2. D12: 作用対象

**誰／何に作用するか**

- Primary Child / Value: `D12.AUD.READER_LISTENER`
- Primary Parent: `D12.AUD`
- Secondary: `D12.AUD.NEXT_RECIPIENT`
- Status: `D`

**判定根拠**

現受信者と、転送によって新たに受信する者が同じ脅威・規則の対象になる。

**この伝承における現れ方**

各受信者は被害候補であると同時に次の伝達者でもあり、転送のたびに新しい作用対象が生成される。

### 2.3.3. D13: 作用機構

**因果源が対象へ何をするか**

- Primary Child / Value: `D13.TRN.PERSON_TRANSFER`
- Primary Parent: `D13.TRN`
- Secondary: `D13.FAT.CURSE_MISFORTUNE`
- Status: `D`

**判定根拠**

既存Pilot Codingでは、人から人への伝播と、不転送者への不運付与を中心機構として採用している。

**この伝承における現れ方**

現実行動としては文面が受信者から次の受信者へ移り、伝承内部では連鎖を止めた者へ不幸が生じるとされる。情報伝播と吉凶作用が一つのルールで結合する。

### 2.3.4. D14: 帰結極性

**結果は正・負・中立・混合か**

- Primary Child / Value: `D14.NEG`
- Primary Parent: なし
- Secondary: なし
- Status: `I`

**判定根拠**

中心Versionの帰結は不幸、事故、病気、死等の負の結果である。

**この伝承における現れ方**

転送は積極的利益を得るためではなく、負の結果を避けるために行われる。恐怖と損失回避が行動を駆動する。

### 2.3.5. D15: 帰結領域

**何の領域が最終的に変わるか**

- Primary Child / Value: `D15.OPP.LUCK_MISFORTUNE`
- Primary Parent: `D15.OPP`
- Secondary: なし
- Status: `I`

**判定根拠**

災厄は広く「不幸」として予告され、事故・病気・死亡等の具体化はVersionによって異なる。

**この伝承における現れ方**

受信者の将来の吉凶全般が、手紙を転送したか否かという情報行動へ従属するとされる。

### 2.3.6. D16: 因果時間構造

**発動条件・原因成立から主作用／主帰結までの関係は、時間上どのように編成されているか**

- Primary Child / Value: `D16.TRN.CHAIN_SPREAD`
- Primary Parent: `D16.TRN`
- Secondary: なし
- Status: `D`

**判定根拠**

受信者から次の受信者へ同じ規則が連続し、各世代で自己複製される。

**この伝承における現れ方**

受信→脅威認知→転送→新受信者という系列が繰り返される。単一事件ではなく、連鎖そのものが時間構造を形成する。

### 2.3.7. D17: 回避・制御方式

**結果をどう回避・制御・利用できるか**

- Primary Child / Value: `D17.CST.TRANSFER_SUBSTITUTE`
- Primary Parent: `D17.CST`
- Secondary: なし
- Status: `D`

**判定根拠**

自分の不幸を避ける手段として同じ文面を他者へ転送することが要求される。

**この伝承における現れ方**

脅威を消滅させるのではなく、次の人物へ渡すことで自分の危険を回避する転嫁構造になっている。

### 2.3.8. D18: 作用レイヤー

**因果効力は伝承内／受容者／社会現実のどこに及ぶか**

- Primary Child / Value: `D18.L1=1; D18.L2=1; D18.L3=0`
- Primary Parent: なし
- Secondary: なし
- Status: `I`

**判定根拠**

既存Pilot Codingでは、L1で「不転送→災厄」、L2で「受信者が恐怖から実際に転送・相談する」を採用し、L3は0としている。

**この伝承における現れ方**

伝承内では連鎖を止めると不幸が起きるとされ、受容者層ではその信念が現実の転送・不安・相談を生む。1977年自治体広報は、地域住民の不安と行政の注意喚起を直接記録している。

自治体・警察対応まで確認できるためL3=0は再検討価値が高い。task 2では既存値を維持し、task 3で再測定する。

## 2.4. 社会的埋め込みの次元

### 2.4.1. D19: 流通範囲

**誰の間に伝承が流通するか**

- Primary Child / Value: `D19.MAS.NATIONAL_PUBLIC`
- Primary Parent: `D19.MAS`
- Secondary: なし
- Status: `D`

**判定根拠**

1970年代に広域流行し、地域社会で公的注意喚起が必要になる社会現象として確認される。

**この伝承における現れ方**

特定地域の秘密伝承ではなく、郵便ネットワークを通じて不特定多数へ拡散できる。

### 2.4.2. D20: 特権情報保持者

- Primary Parent: `D20.NON`
- Secondary: なし
- Status: `I`

**判定根拠**

文面・規則は受信者全員に開示され、秘密の真相保持者を必要としない。

**この伝承における現れ方**

誰でも同じ文面をコピーできることが伝承の存続条件であり、専門家だけが知る秘密情報ではない。

### 2.4.3. D21: 現実アンカー

**実在世界へどの程度固定されるか**

- Primary Child / Value: `D21.A0`
- Primary Parent: なし
- Secondary: なし
- Status: `I`

**判定根拠**

特定地点・事件に依存せず、宛先・人数・災厄事例等を交換して再利用可能であることから、既存Pilot CodingではA0としている。

**この伝承における現れ方**

郵便という実在制度を利用するが、伝承内容自体は一つの場所・事件に固定されない。どの受信者にも移植可能な匿名的規則として流通する。
