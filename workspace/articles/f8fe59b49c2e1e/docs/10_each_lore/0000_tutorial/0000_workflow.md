# 2. Step 0 — 対象Entryと分析単位を確定

## 2.1. Entry_ID

作業開始前に正本データから `Entry_ID` を確認する。

```text
<4桁ゼロ埋めEntry_ID>_<伝承識別名>/
├── <4桁ゼロ埋めEntry_ID>_00_contents.md
└── <4桁ゼロ埋めEntry_ID>_10_analysis.md
```

`0000` はtutorial専用であり、実伝承へ使用しない。

## 2.2. Entry境界

分析単位は、**独立して伝達可能な最小の意味形成モデル**である。

人物名・地名・被害人数・媒体・表現上の細部が違うだけでは通常は分割しない。以下が安定して変わり、世界のルール自体が変わる場合は別Entryを検討する。

- 意味形成対象
- 因果源
- 発動・接触条件
- 作用対象
- 作用機構
- 主帰結
- 回避・制御規則

境界が不明な場合は先に分割せず、主要異伝を `00_contents` に保持し、Version Scope固定時に再検討する。

# 4. Step 2 — 典拠調査とEvidence整理

## 4.1. Evidenceを先にまとめる

可能な範囲で以下を一括して調査する。

- 伝承内容
- 最古確認資料
- 流通媒体・流通範囲
- 異伝・派生・変容史
- 現実社会への外部効果
- 実在地・史実・制度・自然科学的背景等の現実アンカー

## 4.2. Evidence role

- `C` Content: 内容、条件、作用、帰結、物語展開
- `H` History: 成立、流通年代、媒体、変容史
- `X` External effect: 流通により現実社会で実際に起きた効果
- `A` Anchor: 実在地、制度、史実、自然科学的背景等

同一資料が複数roleを持ってよい。

## 4.3. 典拠の優先順位

原則として次を優先する。

1. 一次資料・同時代資料・公式文書
2. 原文ミラー・転載・復刻、原著論文、民俗採録
3. 高品質な研究書・専門家整理・信頼できる二次資料
4. 後代のまとめ・解説

Web資料は到達可能性を確認し、URL、対象範囲、確認日を可能な限り残す。一次資料が見つからない場合も文書化を停止せず、**一次資料未確認**と明示して最も近い資料を使用する。ただし証拠の弱さを隠さない。

## 4.4. Evidence調査の終了条件

調査は資料件数ではなく、**Entry境界・Version Scope・21次元の判定に必要なEvidenceが揃ったか**で止める。

最低限、次を満たすこと。

- 利用可能な最上位の `C` Evidenceで主要内容を再構成できる
- D01〜D04・D19の判定に必要な `H` Evidenceを、確認可能な範囲で確保している
- D18 L3を候補にする場合は `X` Evidenceを確認している
- D21の判定に必要な実在地・制度・史実等は `A` Evidenceで確認している
- 追加の同等以上の資料を確認しても、Entry境界、Version Scope、Primary / Value、Statusのいずれも変わらない状態に達している

`U` を減らすこと自体を目的に探索を延長しない。高品質Evidenceを確認した後に、低品質なまとめを大量収集しても判定が変わらない場合は終了する。

## 4.5. 禁止事項

- 書籍販売ページ・書誌ページだけで物語細部を確認したことにする
- 後代の有名設定を最初期形へ遡及する
- 「古いから口承」「非ネットだから口コミ」と推定する
- 反証資料を「伝承が存在しなかった証拠」と扱う
- 実在地・事件・制度の存在を、そのまま伝承上の因果関係の事実とみなす
- 文書の詳細さとEvidenceの強さを混同する

書誌ページは資料の存在を示す証拠であり、本文に内容がなければ物語細部の直接証拠ではない。

# 5. Step 3 — `*_00_contents.md` の作成

`0000_00_contents.md` の章構造・項目名・順序に従う。`00_contents` は **Evidence / Content layer** であり、分析コードを決める場所ではない。

## 5.1. 記載対象

記載するもの:

- 伝承内容
- 典拠
- 伝承史
- 異伝・派生
- 資料間の差
- 一次資料と後代再話の差
- 証拠上の不確実性
- 現実アンカーの事実関係
- 外部効果を示す証拠

原則として記載しないもの:

- `Entry_ID`
- `Macro_Category`
- `Entry_Type`
- `Version_Scope`
- D01〜D21のコード値

## 5.2. `1.1. summary` の要求密度

summaryは辞書的な2〜3文では不十分である。目標は、**原典を毎回開かなくても、何が起きる／何が主張されるかを再構成できる高密度パラフレーズ**である。

固定の文字数・段落数を目標にしない。十分性は、後続分析を再検討できるだけの具体情報が残っているかで判定する。

### 5.2.1. 時間的進行を持つ伝承

少なくとも以下を連続して把握できるようにする。

- 発端: 誰が、どこで、どの通常状況から始まるか
- 異常の顕在化: 最初に何が通常から外れるか
- 展開: 異常がどう継続・反復・拡大・変質するか
- 対応: 登場人物が何を確認・回避・試行・相談・実行するか
- 転換／エスカレーション: 危険・不可解さ・因果関係がどう強まるか
- 終端: 明示的にどこで語りが終わるか
- 未解決部分: 何が説明されず、何を推測してはならないか

単なる発端→結末のあらすじではなく、**D07〜D17等の分析理由を後から読み取れるだけの人物・場所・物・行為・順序・因果主張**を残す。

### 5.2.2. 非時間的な伝承

俗信・ジンクス・命題型噂・制度俗説等では物語的時系列を作らず、少なくとも以下を明示する。

- 対象となる状況・行為・制度
- 成立条件・適用条件
- 中心命題・規則・因果説明
- 想定される作用・予測
- 帰結
- 回避・制御・利用方法
- 資料上確認できる範囲と、推測・後代解釈の境界

### 5.2.3. summaryで禁止すること

- Candidate Master等の1〜2行要約を言い換えるだけ
- コード定義を文章化するだけ
- 原資料にない心理・真相・因果関係・結末を補う
- 後代設定を初期形へ遡及する
- 「投稿が途絶えた」を死亡・失踪と同一視する
- 書誌・販売ページだけを物語細部の内容証拠にする

## 5.3. `00_contents` 全体の粒度

summaryだけを厚くして終わらない。以下を後から追跡可能にする。

- `1.2. 詳細展開`: summaryの各段階を分解し、可能なら頁・レス番号・採録番号・記事日付等へ対応
- `1.3. 登場人物・主体`: 主体、種別、役割、典拠上確認できる情報、典拠位置
- `1.4. 場所・空間`: 実在／比定／架空／不明を区別
- `1.5. 物・記号・媒体`: 因果や展開に重要な物、身体部位、文書、電話、商品、記号等
- `1.6. 条件・規則・禁忌`: 発動、遭遇、手順、禁止、対処、回避、利用
- `1.7. 異常・不可解な現象／中心命題`
- `1.8. 行動・対応`
- `1.9. 帰結・終端状態`: 明示／暗示／未確認を分離
- `1.10. 未解決点・不確実性`
- `2.1. 最古確認`: 実際の起源と現在確認できる最古資料を分ける
- `2.2. 流通・拡散`
- `2.3. 主要な異伝・派生`
- `2.4. 変容上の重要点`
- `3.1. 内容と典拠の対応表`
- `3.2. 短い原文引用`: 必要最小限とし、長文転載しない
- `3.3. 証拠上の保留事項`

`00_contents` 単独で、主要構造・異伝・Evidence限界を再構成できる状態を目指す。

# 6. Step 4 — Version Scopeと分析条件の固定

`00_contents` 完成後、`10_analysis` 作成前に **Version Scopeを固定する**。

Version Scopeは、「どの伝承形・期間・媒体層までを一つの分析対象としてコードするか」を定める分析条件である。

## 6.1. 既定のScope選択規則

別途明示されたScopeがない場合は次の順で固定する。

1. 原投稿・同時代記録等で**成立時のまとまった伝承形**を直接確認できる場合、その最古のまとまりを既定Scopeとする。
2. 後代要素は、同じ意味形成核を保ち、分析上不可欠であることを説明できる場合だけ含める。
3. 後代の創作翻案、世界のルールを変える安定異伝、因果源・発動条件・作用・帰結を追加変更する派生は既定Scopeから外す。
4. 成立時のまとまった形が確認できない場合は、複数資料で確認できる**最も早い安定した共有核**までScopeを狭める。競合する異伝を無理に統合しない。

Scopeを広げて情報量を増やすことより、**一つの意味形成モデルを一貫して測れること**を優先する。

## 6.2. Scopeに含める／分離するもの

含めるもの:

- 共有核を構成する主要形
- 当該Entryの意味形成モデルを維持する主要異伝
- 分析上必要な流通・変容層

原則として分離するもの:

- 後代の創作翻案
- 世界のルールを変える安定異伝
- 原型と因果源・発動条件・作用・帰結が異なる派生
- Evidenceが弱く共有核とみなせない有名設定

異伝を広く保持する `00_contents` と、実際にコードするVersion Scopeは同一ではない。Scope固定前にD07〜D18を確定してはならない。

# 7. Step 5 — `*_10_analysis.md` の作成

`0000_10_analysis.md` の構造・項目名・順序へ厳密に従う。`10_analysis` は **Analytical definition / Coding layer** であり、コード表のMarkdown転記ではない。

## 7.1. 基本情報

基本情報はtutorialで定めた以下のみとする。

```text
- Entry_ID
- 伝承エントリ名称
- Macro_Category
- Entry_Type
- Version_Scope
```

独自の `Evidence_Rank`、`ネット発祥`、`主な成立・流通期` 等を追加しない。

## 7.2. コーディングの思考順と完成文書の順序

分析時は `30_urban_legend_analysis_coding_rules.md` に従い、原則として次の順で判定する。

```text
D07 → D08 → D09 → D10
→ D11 → D12 → D13 → D14 → D15 → D16 → D17 → D18
→ D01 → D02 → D03 → D04 → D05 → D06
→ D19 → D20 → D21
```

意味形成・因果構造を先に捉え、来歴やジャンルから内容構造を逆算しない。完成文書はtutorialどおり **D01 → D21** の順に記載する。

## 7.3. 各次元の最低記載内容

各次元は原則として次の順で記載する。

```text
コード値
↓
判定根拠
↓
この伝承における現れ方
↓
必要なら境界・留保
```

実装上はtutorialの以下の項目名を使う。

```text
- Primary Child / Value:
- Primary Parent:
- Secondary:
- Status:

**判定根拠**
...

**この伝承における現れ方**
...
```

各次元で必ず、**「この概念次元からこの伝承を見ると、具体的に何が起きる／何が主張される／どのような構造を取るのか」**へ答える。

## 7.4. 「判定根拠」

- `00_contents` のどの内容・典拠がコード選択を支えるか
- `D`: どの直接証拠に明示されるか
- `I`: どの事実とコード定義から推論したか
- `U`: 何が確認できず一意に判定できないか
- `NA`: なぜ伝承構造上その次元が成立しないか
- `C`: どのVersion・資料・異伝が競合するか

## 7.5. 「この伝承における現れ方」

ここはコード定義の言い換えではない。伝承固有の人物、場所、出来事、言葉、条件、行為、帰結を使い、コードが物語・命題内で具体的にどう機能するかを書く。

目標は、

```text
原資料上の具体的展開
→ 分析者の解釈
→ コード
```

というトレーサビリティを確保することである。

例: きさらぎ駅のD13を `SPATIAL_DISTORTION` とする場合、「空間異常だから」で終えない。通常路線では説明できない接続、見知らぬ駅への到達、既知の鉄道網・地理情報へ現在地を接続できないこと、徒歩でも通常空間へ復帰できないことを示し、**未知の場所というだけでなく既知空間同士の接続関係が崩れている**と説明する。一方、初期版が「別世界」を明言しないなら、後代の異界解釈を遡及させない。

## 7.6. 21次元すべてに自然言語説明を付ける

対象は以下の21次元すべてである。

1. D01 生成年代
2. D02 最古確認流通媒体
3. D03 確認流通媒体ポートフォリオ（Version Scope）
4. D04 生成・変容パターン
5. D05 提示形式
6. D06 真実性提示
7. D07 意味形成対象
8. D08 意味形成契機
9. D09 意味付与操作
10. D10 因果源存在論
11. D11 発動・接触条件
12. D12 作用対象
13. D13 作用機構
14. D14 帰結極性
15. D15 帰結領域
16. D16 因果時間構造
17. D17 回避・制御方式
18. D18 作用レイヤー
19. D19 流通範囲
20. D20 特権情報保持者
21. D21 現実アンカー

D01〜D06・D19〜D21は、物語中の展開に無理に限定せず、**成立・流通・提示・現実への固定のされ方**が具体的にどう現れるかを書く。D07〜D18は伝承内部の具体的展開との対応を特に厚くする。

## 7.7. Primary / Secondary / Parent / Status

- Primary: その次元で意味形成構造を最も強く規定するChild
- Secondary: Primaryだけでは失われる独立した追加構造。単に「少し関係する」ものは付けない
- H3では `D/I` 時にPrimary exactly 1、Secondary 0〜2
- ParentはChildから一意に導出し、独立に判断しない
- `D`: 典拠に直接明示
- `I`: Evidenceと定義から合理的に推定
- `U`: 資料不足
- `NA`: 構造上非該当
- `C`: 同一Scope内で競合

`U` を最もありそうな値で埋めてはならない。

## 7.8. 近接Childのtie-break

複数Childが候補になる場合は、`30_urban_legend_analysis_coding_rules.md` の共通tie-breakを用いる。

優先順位は、**中心質問への直接性 → Evidenceの強さ → 意味形成構造への不可欠性 → 未確認前提を必要としない保守性**である。独立した追加構造だけをSecondaryへ残す。

## 7.9. 禁止する薄い書き方

以下のような定型文だけで各次元を終えてはならない。

- 「0180と同様、コード定義と記録内容から合理的に推定した判定を保持する」
- 「Pilot Codingの既存判定を文書化した。直接証拠は00_contents参照」

これらはコード移植の説明であり、その伝承の分析ではない。必ず当該伝承固有の具体内容へ戻す。

## 7.10. 文書増補と再コーディングを混同しない

既存Entryを**文書化・記述密度向上だけの目的で増補する場合**、既存D01〜D21・Statusを、文章を厚くしたことだけを理由に変更しない。

再調査により現行コードとEvidenceが明らかに噛み合わない疑いが生じた場合は、留保・再検討候補を明示し、必要なら**再コーディングを別の明示的な作業として行う**。文書増補と再コーディングを黙って同時実行しない。

新規Entryや、最初から再コーディングを目的とする作業では、現行の `10 / 20 / 30` に従いEvidenceからコードを判定する。

# 8. Step 5で特に注意する次元

## 8.1. D01

最古確認年と生成年代を混同しない。「遅くとも2008年に存在」は「2000年代に生成」とは限らない。安全に年代帯へ写像できなければ `U`。

## 8.2. D02

起源媒体ではなく、**現在の証拠で最古に確認できる実流通媒体**。「古いから口承」「非ネットだから口コミ」「後代研究書があるから書籍」は禁止。

## 8.3. D03

Version Scope内で、実際に受容者へ流通したことを確認できる媒体。研究DBで見つかることや、現在Web検索可能なこと自体は流通媒体Evidenceではない。

## 8.4. D04

変容Evidenceがないからといって `STABILIZED_CANON` や単発固定へしない。変化を確認できなければ `U` を検討する。

## 8.5. D05 / D06

研究者の記述形式ではなく、伝承が受容者へどう提示され、どの程度の「本当らしさ」を要求するかを見る。

## 8.6. D07

「この伝承がなければ何が説明されないまま残るか」を一文で言語化してから選ぶ。結果や原因を意味形成対象と混同しない。

## 8.7. D08 / D11

- D08: なぜ問題として立ち上がるかという手掛かり
- D11: 因果系へ入る発動・接触条件

両者を混同しない。D11では、日常行為が単なる文脈で再現可能な発動規則でない場合、受動発生・偶然遭遇系をPrimaryとし、行為は必要ならSecondaryとする。

## 8.8. D09

不可解さを理解可能にする認知操作を見る。`MYSTERY_LABEL` は原因を確定せず謎として安定把握する場合、`DELIBERATE_NONRESOLUTION` は非解決自体が意図的提示戦略であるEvidenceがある場合に限る。単に未解決・複数説というだけでは後者にしない。

## 8.9. D10

原因を何として世界に置くか。明示的主体がなくても、異常が一貫して場所・経路・接続関係に依存して成立するなら対応する場所・時空系Childを `I` で選べる。`ALTERNATE_WORLD` 等の強い存在論はScope内で明示・安定化している場合に限る。

## 8.10. D13

「何をするか」をコードし、D15の最終帰結と分ける。`MANIFEST_ONLY` を資料不足の代用にしない。

## 8.11. D15

最終的に何の領域が変わるかを見る。身体被害・死亡・失踪が確認されず、所在・帰還・真相が未確定のまま終端となる場合は `UNCERTAINTY_PRESERVED` をPrimary候補とする。「投稿が止まった」だけで死亡・失踪にしない。

## 8.12. D16

伝承の流通年数ではなく、**発動条件から主作用・主帰結までの時間構造**。静的命題は `STA` を検討し、非物語型だから `U` にしない。

## 8.13. D17

対処法が確認できないことと「不可避」は別。不可避には明示Evidenceが必要。対処不明なら `U` を検討する。

## 8.14. D18

- L1: 伝承内部の因果作用
- L2: 読む・聞く・受信する現実側の受容者が、伝承内容上の因果対象になる
- L3: 噂の流通により現実社会で確認可能な行動・制度・市場等の結果が生じる

L3には `X` Evidenceが必要。「影響しそう」では付けない。通常の説得・不安・行動変化をL2と混同しない。

## 8.15. D19

媒体ではなく社会的流通範囲を見る。

## 8.16. D20

単に噂を知る人ではなく、真相・追加情報・回避情報を偏って保持する主体を見る。

- 資料が情報保持者を扱っていないだけなら `U`
- Version Scope内で、主人公・家族・警察・専門家・共同体・参加者等のもっともらしい保持者／権威が実際に探索・照会・提示され、それでも誰にも真相・追加情報・有効な制御情報が成立しないなら `NO_ONE_KNOWS` を `I` とできる

これは「世界中の誰も知らない」という断定ではなく、**Scope内に特権情報保持者が成立していない**という情報構造の判定である。

## 8.17. D21

典拠が実在することと、伝承内容が現実へ固定されていることを分ける。実在地が舞台なだけなのか、史実・制度・実在物が意味形成モデルの成立に不可欠なのかを見る。

# 10. Step 7 — GitHub反映・push後検証

原則として **1 Entry = 1 commit** とする。通常は次の2ファイルだけを同一commitへ含める。

```text
<Entry_ID>_00_contents.md
<Entry_ID>_10_analysis.md
```

片方だけ変更が必要なら1ファイルでもよい。複数伝承を同一commitへまとめない。テストファイルや一時ファイルをmainへ作らない。

書き込み直前に最新mainを確認し、commit後は差分を検証して想定外ファイルがないことを確認する。push後に必要に応じてファイルを再取得し、最終状態を確認してから完了とする。

- 起源・最古確認・後代派生を区別している

- 1 Entry単位のcommitになっている
- commit差分を検証した

# 13. 最重要原則

件数消化や文章量そのものを目的化しない。

`00_contents` は短い百科事典記事ではなく、**証拠に忠実な高密度の伝承記録**にする。

`10_analysis` はコード一覧ではなく、**21概念次元を通して1つの伝承を読む分析文書**にする。

Evidenceが弱い箇所は弱いまま保持し、推測で埋めない。最終的に、後から人間または別コーダーが、

```text
Evidence
→ 伝承内容
→ Version Scope
→ 分析判断
→ コード
```

を再構成できることを重視する。

# 14. Workflow変更時の回帰試験 — 0180 きさらぎ駅

`0180 きさらぎ駅` を、本workflowおよびコーディング規則の**regression test benchmark**とする。

`0000_workflow.md` または `30_urban_legend_analysis_coding_rules.md` の変更が、Entry作成・Version Scope・コード判定へ影響し得る場合は、変更完了条件として次を確認する。

## 14.1. 試験方法

1. 既存の `0180_00_contents.md` と `0180_10_analysis.md` を参照せず、0180の原資料・外部典拠から本workflowに従って `00_contents` 相当を再構築する。
2. その再構築結果と現行の `10 / 20 / 30` のみを使い、Version ScopeとD01〜D21を再判定する。
3. 判定完了後に、正本 `0180_10_analysis.md` と比較する。

## 14.2. 合格基準

文章表現の一字一句の一致は要求しない。以下を要求する。

- Version Scopeが意味的に同一である
- D01〜D21の `Primary Child / Value` がすべて一致する
- Secondaryがすべて一致する
- Statusがすべて一致する
- ParentはChildから導出した結果として一致する
- 主要な判定根拠が同じEvidenceと同じ論理関係に基づく

**21次元のいずれか1つでもコードまたはStatusが異なる場合、回帰試験は未合格とする。**

## 14.3. 不一致時の扱い

不一致を「コーダーの好み」で処理しない。次のどちらかを特定する。

- benchmarkである0180側の既存判定が現行Evidence・規則に照らして誤っている
- workflow / coding rulesに、複数の合理的判定を許す不足・曖昧さが残っている

後者の場合は、**その不一致を生んだ最小の規則だけを補強する**。別の伝承を追加benchmark化したり、全次元の規則を再設計したりして作業を膨張させない。

本回帰試験の目的は、0180を暗記して同じ回答を出すことではなく、**同じEvidenceから独立に同じVersion Scope・21次元へ到達できるworkflowであることを保証すること**である。
