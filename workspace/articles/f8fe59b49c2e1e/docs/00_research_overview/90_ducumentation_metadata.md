# 1. Research overview ドキュメント一覧と責務分担

`docs/00_research_overview/` 配下の各文書は、同じ分析体系を異なる抽象度・目的で記述する。内容の重複による不整合を避けるため、各文書の責務を以下のとおり分離する。

| 文書 | 責務 | 主に記載する内容 | 原則として記載しない内容 |
|---|---|---|---|
| `10_urban_legend_analysis_axes_theoretical_design.md` | **理論設計** | なぜその概念次元を置くのか、各次元が何を測るのか、次元間の理論的境界、分析単位、データ型、情報量評価の原則、研究問いとの対応 | Parent / Childコードの完全一覧、個別コードのinclude / exclude条件、具体的な判定フロー |
| `20_urban_legend_parent_child_code_system.md` | **測定体系・コード体系** | 理論次元をどのParent / Child / Value / bitで測定するか、コードID、Child→Parent対応、カテゴリ定義、各次元の測定粒度 | 新しい理論次元を独自に導入すること、証拠からコードへ到達する詳細な操作手順 |
| `30_urban_legend_analysis_coding_rules.md` | **コーディング運用規則** | 実際の資料・証拠からどのようにコードを判定するか、Evidence role、Dimension Status、Primary / Secondary選択、include / exclude、境界事例、判定フロー | 理論次元そのものの新設・廃止、Parent / Childコード体系の独自変更 |
| `90_ducumentation_metadata.md` | **文書管理規則** | Research overview文書群の責務分担、文書構造、見出し番号、記載上の共通ルール | 個別の理論内容、コード値、コーディング判定 |

責務分担の基本原則は、次のとおりとする。

- `10` は **「なぜ・何を測るか」** を定義する。
- `20` は **「それをどの値で測るか」** を定義する。
- `30` は **「証拠からその値をどう判定するか」** を定義する。
- `90` は **「これらの文書をどう管理・構造化するか」** を定義する。
- 下位文書は上位文書の責務を再定義しない。`20` は `10` の理論を測定可能なコードへ具体化し、`30` は `20` のコードを再現可能に適用するための規則へ具体化する。
- 同一内容を複数文書へ完全複製しない。別文書の詳細が必要な場合は、要点のみ記載し、正本となる文書を参照する。
- 理論次元の追加・削除・意味変更は `10` を起点として行い、必要に応じて `20` と `30` の整合性を更新する。
- Parent / Child / Value / bitの追加・削除・統合・分割は `20` を起点として行い、`10` の理論的定義および `30` の判定規則との整合性を確認する。
- 証拠要件・判定フロー・Primary / Secondary選択規則などの運用変更は `30` を起点として行い、必要に応じて `20` のコード定義および `10` の理論定義との整合性を確認する。
- 文書間で記載が競合した場合、理論概念については `10`、コード値・コード体系については `20`、具体的な判定手順については `30` を当該責務範囲の正本とする。

# 2. 文書構造ルール

- 見出しには必ず、対応するレベルの接頭辞番号を付けること。
- 接頭辞番号は上位見出しの番号を継承すること。
- 同一階層の見出しは連番とすること。
- 見出しレベルを飛ばさないこと。
- 見出しレベル1を単独のドキュメントタイトルとして使用してはならない。
- 同一見出し階層内において、その数が一つの見出しを作成してはならない（*1）。
- 原則として、以下で指定された章・節を省略しないこと。
- 見出しを追加する場合も番号体系を維持すること。

| 見出しレベル | 接頭辞番号 | 見出し名称（日本語） | 見出し名称（英語） |
|---|---|---|---|
| # | 1. | 章 | chapter |
| ## | 1.1. | 節 | section |
| ### | 1.1.1. | 項 | subsection |
| #### | 1.1.1.1. | 目 | subsubsection |

*1）例

```text
# 1. aaa
## 1.1. aaa-1
### 1.1.1. aaa-1-1
### 1.1.2. aaa-1-2
```

この場合、`## 1.1. aaa-1` は、その見出しレベル（≒カテゴリ）に子見出しが1つしか存在しないため、独立した階層を作成する意味がない。

# 3. 伝承別ディレクトリ命名規則

## 3.1. Entry_ID と接頭辞番号

`docs/10_each_lore/` 配下に作成する各伝承エントリのディレクトリは、以下の形式とする。

```text
<4桁ゼロ埋めEntry_ID>_<伝承識別名>
```

接頭辞番号には、`docs/20_analysis_summary/urban_legend_parent_child_full_application_v1.xlsx` に記載された当該伝承の `Entry_ID` を使用し、**4桁のゼロ埋め**で表記する。

例:

```text
Entry_ID = 180
→ 0180_kisaragi_station
```

ディレクトリの並び順、作成順、調査順を根拠として独自に番号を採番してはならない。伝承エントリとディレクトリの対応は、上記Excelの `Entry_ID` を正本とする。

新規調査・再調査・既存伝承の文書化を行う際は、作業開始前に対象伝承の `Entry_ID` を確認し、その4桁ゼロ埋め値をディレクトリ接頭辞として使用する。

## 3.2. 予約番号と例外

`0000` はテンプレート・チュートリアル用の予約番号とし、実データの伝承エントリには使用しない。

```text
docs/10_each_lore/0000_tutorial/
```

実データの伝承ディレクトリでは、接頭辞番号とExcel上の `Entry_ID` が一致していることを確認する。ディレクトリ名の伝承識別名部分を変更しても、同一Entryである限り接頭辞番号は変更しない。
